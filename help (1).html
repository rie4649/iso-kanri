❓ ISO管理の使い方（よくある質問）

「これはどこ？」と聞かれたら、ここを見せれば分かるようにまとめました
まずはこれだけ
① 毎日：ホームの「✅ 今やること」と「📌 終わっていないこと・期限」を見て、赤いものから片づける
② 何か起きたら：ホームの「🚨 何かあったとき」から記録する
③ どの記録にも：記録者の名前と日付が残る（名前は1回入れれば次から自動）
こんなときは？
1年の流れ（年度は8月〜翌7月）
毎月クリーン度チェック（月2回）・安全衛生パトロール・軽油・ライフライン（前の月の分）・顧客対応の気づきを書き写す
3か月ごとフロン簡易点検
8月自覚教育（全社員）・環境側面調査記録（取扱量）・環境側面の見直し・取引先チェック表・委託契約状況集計表
9月ごろ内部監査の計画（日程・分担）
10月〜2月内部監査（チェックシート・アンケート）→ 指摘があれば是正処置 → 2か月後に確認
11月緊急事態の訓練・テスト
1月末半期末の目標の評価
年1回水質検査・騒音チェック・法令の順守評価（A-05チェックシート）・測定機器の点検
7月マネジメントレビュー（資料は自動で作れる）・文書の見直し・来年度の目標を決める
年7〜8回環境管理会議（議事録に記録）
ことばの意味
EMS文書ISOのために会社で決めた書類と記録。番号（例 EMS-A-05）が付いている。一覧は「EMS文書管理」
版書類を直したときの番号（01、02…）。「この表でPDFを作る」で新しい版ができ、古い版も残る
確認・承認作った人とは別の人が中身を見て「確認」、責任者が「承認」する。直すとやり直しになる
是正処置問題（不適合）が起きたときに、原因を調べて二度と起きないようにすること
著しい環境側面会社の仕事のうち、環境への影響が大きく、特に管理するもの（A-08の表）
マネジメントレビュー1年の結果を社長に報告して、指示をもらうこと（7月）
環境への取り組み審査・視察・プロジェクターで見せるための画面（見るだけ）
🔧 アプリを管理する人へ（引き継ぎ）
しくみ：画面はGitHub（rie4649/iso-kanri）のファイルで、GitHub Pagesで公開しています。記録はFirebase（プロジェクト sekine-store）のデータベースに入っています。直すときは、直したファイルをGitHubに上書きでアップするだけです（データは消えません）。
ほかのアプリとのつながり：車両（master_vehicles）・従業員（employees）・就業カレンダー・契約は「マスタ管理」アプリのデータを読んでいます。ここでは直さず、マスタ管理で直します。
守り：①月1回「💾 バックアップ」でZIPを取り、会社のパソコンやUSBにも置く　②間違えて直した・消したときは「🕘 直した履歴」で元に戻す　③写真やPDFの中身はバックアップから戻す。
最初の1回だけ動く処理：最初の計画や項目を自動で入れる処理は、データベースの「isoSettings / seeds」に印を付けて、2回目からは動きません。入れ直したいときは、その印を消します（わからなければClaudeに相談）。
直してほしいとき：Claudeに「ISO管理の○○の画面を、□□にしたい」と画面の写真と一緒に頼むと、直したファイルを作ってくれます。
ファイル何の画面・部品か
index.htmlホーム（今やること・期限）と、毎月の記録（パトロール・軽油・水質など）・カレンダー・会社情報
plan.html ＋ registers.jsISOの計画・記録の表（課題・環境側面・リスク・目標・苦情・内部監査など）。表の項目を増やすときは registers.js を直す
plan-seed.js計画の表に最初に入れた内容
docs.html ＋ ems-docs.js ＋ ems-seed.jsEMS文書管理（書類の一覧・版・PDF・ISOの要求と書類）
show.html環境への取り組み（審査・視察で見せる画面）
summary.html ＋ mr-report.js年間サマリーと、マネジメントレビューの資料の自動作成
kiroku.html内部監査の結果・是正処置
survey.html ＋ survey-templates.js ＋ survey-items.js委託先調査票の回答（会社ごとの質問と答え）
reports.html ＋ reports-due.js届出・報告の期限一覧（期限の計算は reports-due.js）
newhire.html新入社員研修
photos.html写真の記録
volumes.html ＋ volumes-seed.js環境側面調査記録（取扱量）
custlog.html / shokaki.html / permit.html / skills.html顧客対応の進捗 / 消火器・防火管理 / 許可の内容 / 力量（資格）
kyoka.html ＋ permit-sync.js許可一覧。有効期限は業務管理の許可証管理（kyokaShoumei）を読むだけで、許可証PDF（マスタ管理で登録）と組み合わせて食い違いを知らせる。知らせ始める日数は permit-sync.js の WARN_DAYS
manual-text.js環境マニュアル（EMS-A-01 第10版）の本文の写し。新入社員研修の「📘 環境マニュアル」でその節を開くのに使う。マニュアルを改訂したら作り直す（「原本を開く」はEMS文書管理の A-01 を開く）
tenken-stats.js点検ラクラク（別のFirebase：tenken-rakuraku の Realtime Database）の点検記録を読むだけで数える。終わった月は端末に覚えて読み取りを減らす。表示は環境への取り組みの「車両点検の実績」・年間サマリー・ホーム（未対応の不具合報告）
phone-complaint.js電話依頼の中から苦情かもしれないものを見つけて、コミュニケーション・苦情の表に1回押すだけで入れる（電話依頼アプリには書き込まない）
library.html ＋ library.js書類の置き場（PDF・写真を1回入れると、ホームのフォルダ・研修の教材・環境への取り組みの「資料」から見られる）
vehicles-list.html車両の愛称と車両番号の一覧（マスタ管理から自動）
backup.html / history.html ＋ history.jsバックアップ / 直した履歴（history.js が全部の画面の保存を自動で記録）
recby.jsどの記録にも「記録者・記録日」を自動で付ける部品
help.html / biz.cssこの使い方の画面 / 画面の見た目（色・文字）
